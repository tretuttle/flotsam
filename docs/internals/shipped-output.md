# Shipped output

The rule: everything in the packed XPI is production build output. No source, no source maps, no development builds, nothing unminified. `pack` and CI run `apps/extension/scripts/check-xpi.ts` on the archive and fail naming the file and the rule.

## The rules are one table

`scripts/xpi-rules.ts` lists every rule with what it inspects, how it decides, and the planted archive that proves it. `check-xpi.test.ts` runs the evasions from both verification reports and requires the exact set of rules that file fails. A rule cannot be added without a plant, and a plant whose rule is removed fails. To add a rule, add a row.

## Decisions

- **Minified means the build's minifier cannot improve it, and no line break sits between tokens.** For each script and stylesheet the check runs the same minifier the build runs, with comments kept, and fails when the output is smaller by more than the margin. A minifier that throws on a file fails the file with its error, because a file nobody can judge is not minified. The margin is `min(512, max(32, 3% of the file))`, set from measurements of the real build: `shared/framework.js` (218521 bytes) saves 302 bytes (0.14%, from whole-bundle renaming and merged duplicate functions) and every other file saves 0, 3, 5 or 7. The floor is 4.6 times the largest small-file saving and the 3% only gives a small file that another minifier wrote some slack. The ceiling is 1.7 times the bundle's 302 and binds from 17067 bytes up, so a large file hides about a kilobyte of readable code at most (8 one-line copies of a 210 byte function fail). One such function saves 89 bytes, under the margin, so size alone cannot see a single function in a large bundle; the margin is the detection floor. A script another minifier wrote saves more on a second pass (measured with the build's minifier: js-yaml 1.5%, less 2.1%), so a large one fails; extension.js bundles and minifies every script it ships, so none reaches the XPI except through the build's minifier. A React upgrade or a minifier bump that moves the bundle's saving past 512 fails here by design: re-measure and move the ceiling in `xpi-rules.ts` with the new numbers. A minifier also leaves no line break between tokens, so one outside a string, template, regular expression or comment fails; the line holding a kept legal comment is the only exception.
- **A string that holds readable source is judged like a file.** A script string or template quasi with at least two line breaks, at least 120 characters and code keywords is judged as a script of its own when it parses, so a data table beside the function cannot dilute it. When it does not parse, a minifier error is not a pass: more than two lines that end in a brace or look like a statement fail `string-holds-source`. Prose with the words `if` or `return` has no such lines and passes.
- **A file's extension says what it claims to be; the rules read its bytes.** A `.json` file must parse as strict JSON and must not be a source map. A `.png` must start with the PNG signature. A `.svg` must hold an `<svg` element and a `.html` a doctype or `<html`. A first-byte signature for ZIP, gzip, WebAssembly, ELF, Mach-O, PDF, RAR or 7-Zip fails `foreign-content`, so an archive or wasm module cannot ship under an allowed suffix regardless of its name. The build's icon SVG is one line plus a trailing newline; any other line break fails.
- **Comments are found by the build's own parser.** `oxc-parser` reads scripts, so `/*` inside a string or a regular expression is data, and a comment after `a++/2` is still a comment. `sourceMappingURL` is looked for in those comments only, which keeps the same text inside a string legal. A legal comment is at most 400 characters and holds no code punctuation or keyword; `==` counts, because a comment of calls and comparisons is a program.
- **A source map is an object, not a file name.** The check looks for a version 3 map object at any offset in every file's bytes, for any parsed JSON object that is one (so `\u0076ersion` does not hide it), and inside JSON strings and script strings. A map behind a NUL byte, inside an SVG, after a PNG, or as a JSON string value fails.
- **Every script and style the markup would run is judged.** `inlineBodies` reads closed and unclosed `<script>` bodies, `data:` URLs in `src`, `on*` handlers, `javascript:` URLs (after the browser's tab, line break and percent decoding), `style` attributes and, recursively, an iframe `srcdoc`. Attribute values are decoded with numeric and named character references first.
- **A development build is a marker, not a file name.** `NODE_ENV`, `jsxDEV`, `__DEV__` and the React DevTools banner fail in any spelling, including the bracket form, because a production build folds them away.

## The parent's result shape is checked at run time

`experiment/parent-api.ts` builds the API object from injected reads, so `contract.test.ts` runs the real handler in Node. It compares `Object.keys` of the result, the browser object and both toolbox shapes with `environmentKeys` in `contract.ts`. TypeScript checks excess properties only on a fresh literal; a returned variable with an extra key passes typecheck and fails this comparison.

## Trap: extension.js bundles scripts from `scripts/`

extension.js reserves a project folder named `scripts/` and bundles into the build any file in it that imports no Node built-in. A new tooling module in `apps/extension/scripts/` shipped inside the XPI. `extension.config.js` sets `folders: { scripts: false }`, and `dev-only-file` fails any `scripts/` path in the archive.

## What the check does not see

An HTML comment holding source (the page never runs it), a source map split across two files, a map base64-encoded in a script string, readable source split over strings of one line break each, and duplicate zip entries. Each needs a deliberately hostile author and none changes what the browser runs. A script nested 20000 levels deep crashes the native parser (observed; 2000 levels pass), which ends the check without a FAIL line and fails CI.
